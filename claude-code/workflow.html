Workflow Claude đang làm

Bạn đưa yêu cầu và chỉ dừng để duyệt vài cổng. Giữa các cổng, Claude tự đi bước tiếp theo và ghi việc đang làm xuống thư mục context/. Code mới chỉ xuất hiện khi code sẵn, nền tảng và dependency đang cài không làm đủ. Spec đã duyệt và conventions.md vẫn thắng.

Bạn Nói yêu cầu. Duyệt spec, plan, rủi ro, và nguyên nhân bug. Claude hỏi bạn ở những chỗ đó.
Skill Bộ hướng dẫn trong .claude/skills/. Skill ai-dev-workflow chọn bước tiếp theo. Lúc plan, lúc GREEN và lúc review, skill bắt dừng ở cách ngắn nhất vẫn đủ yêu cầu đã duyệt.
ai-dev.js Không phải một phase. Đứng ở mép các bước: trỏ việc đang làm, đóng cổng, đổi phase, ghi evidence, và chặn test khi sổ chưa sẵn sàng. Không viết code sản phẩm.

      Feature

      BướcLệnhSổ làm gì
      Onboard — Không gọi. Bước này không có status.json. /feature thấy context/project/ trống thì quay lại đây trước.
      Require claim
      phase set REQUIRE      		 Trỏ context/ACTIVE.json vào feature vừa tạo và ghi phase. Chưa có cổng để duyệt.
      Gate 1 gate approve spec Ghi gates.spec = approved kèm sha256 của 02-spec.md. Lời “nghe ổn” không đi qua lệnh này thì cổng vẫn pending.
      Plan phase set PLAN
      validate      		 Vào phase PLAN. Nếu spec đã duyệt mà file đã khác hash, validate báo drifted. Chưa chặn việc viết plan.
      Gate 2 gate approve plan
      phase set BUILD      		 Hash nối 03-plan.md với 04-test-cases.md. phase set BUILD ghi diffBase = commit HEAD nếu còn trống.
      Build assert-build-ready
      evidence append
      gate approve risk
      phase set REVIEW      		 Trước test: Gate 1 và Gate 2 approved, hash khớp, đúng nhánh feat/<id>, ACTIVE.json trỏ đúng id. gates.risk đang pending thì fail. Mỗi task và suite cuối ghi một dòng evidence. validate từ chối khi tddAttempts quá 5. Hết task thì sang REVIEW.
      Review validate Không đọc diff và không đóng finding. Chỉ từ chối khi reviewRounds quá 3. Finding Critical/Major trong 06-review.md được đọc lúc Done.
      Deliver phase set DELIVER
      evidence append      		 Đổi phase. Có CI thì một dòng evidence, không dán log. Không merge.
      Done assert-done
      phase set DONE      		 Phase phải đã tới REVIEW, DELIVER, hoặc DONE. 06-review.md không còn Critical/Major open. Khi phase là DONE, dòng Result phải là PASS. workType: code cần evidence suite với exit code 0.

      Bug

      BướcLệnhSổ làm gì
      Báo cáo claim
      phase set BUGFIX      		 Trỏ ACTIVE sang bug và ghi phase. Không có Gate 1, Gate 2.
      Tái hiện evidence append --kind bug, bắt buộc --exit, --command, --summary. Một dòng, không dán log.
      Điều tra — Không gọi. Subagent chỉ đọc và viết 02-investigation.md.
      Cổng nguyên nhân gate approve rootCause Ghi gates.rootCause = approved kèm summary. Bug chỉ có cổng này.
      Sửa assert-build-ready
      evidence append
      validate      		 Root cause phải approved, đúng nhánh fix/<id>. validate từ chối khi bugFixAttempts quá 3. Xong thì đi Review, Deliver, Done của feature.
      Review → Done cùng feature assert-done cho bug đòi root cause approved và evidence bug hoặc suite exit code 0. Không đọc 06-review.md theo luật feature.

      Bọc quanh mọi phiên, không thuộc một phase

      KhiHookSổ làm gì
      Mở phiên claude-session-start In ACTIVE, phase, và bước kế (session-context). Không có việc đang làm thì bảo chạy /onboard hoặc /feature / /bugfix.
      Trước Bash claude-pre-bash Chỉ lệnh test (npm, pytest, go test, …). Feature ở BUILD, REVIEW, DELIVER, hoặc bug ở BUGFIX, REVIEW, DELIVER. assert-build-ready fail thì hỏi bạn, không tự cho chạy. Lệnh khác vẫn đi.
      Agent dừng claude-stop Chưa DONE mà hash drifted hoặc vượt giới hạn vòng lặp thì in cảnh báo. Không chặn lượt đó.

      Ba hook này có trong file, nhưng repo hiện chưa có settings.json gắn vào Claude, nên chúng chưa tự chạy. Skill gọi lệnh trực tiếp. Cùng file còn bốn hook Cursor (cursor-session-start, cursor-before-shell, cursor-subagent-start, cursor-stop) cho pack .cursor; trang này chỉ gắn hook Claude vào các bước.

      Bên trong BUILD, nếu là code

      Một task một lúc. Test đỏ viết trước. Thang dưới đây chỉ chọn code sản phẩm sau khi test đã fail đúng lý do.

      REDViết test của task. Test phải fail đúng lý do.
      →
      GREENDừng ở bậc đầu tiên còn làm đủ test của task.
      →
      REFACTORDọn tên. Theo conventions.md. Test vẫn xanh.
      1. 1Đã có trong repo: helper, component, pattern. Dùng đúng cách code xung quanh đang dùng.
      2. 2Thư viện chuẩn hoặc tính năng của nền tảng, trừ khi dự án đã có cái của mình.
      3. 3Dependency đang cài. Không thêm thư viện chỉ vì vài dòng.
      4. 4Một dòng đọc là hiểu.
      5. 5Phần code tối thiểu để test chuyển xanh.

      Spec đã duyệt và conventions.md thắng thang này. Không cắt validation ở biên tin cậy, xử lý lỗi để khỏi mất dữ liệu, bảo mật, accessibility.

      Hết mọi task: chạy full test, lint, typecheck, build một lần, ghi một dòng evidence, rồi tự sang Review. Review bắt code dựng lại thứ đã có, hoặc dependency mới chỉ vì vài dòng.

      Plan cũng đi thang này trước khi chia task, và không bỏ acceptance criterion để plan ngắn hơn. Việc docs, infra, hoặc config không bịa unit test. Mỗi task chạy check CK-xx đã ghi trong plan.
